# Meridian — Methodology and Results

## How we tested

### The measurement axes

Meridian evaluates RAG pipeline strategy choices on two layers that never contaminate each other:

**Layer 1 — Deterministic retrieval taxonomy (no LLM judges).** Every retrieved chunk is classified against ground-truth character offsets into six failure types:

| Code | Failure type | What it means |
|------|-------------|---------------|
| DRM | Document retrieval miss | Retrieved from the wrong document |
| CBF | Chunk boundary failure | Right document, answer straddles a chunk split |
| SGP | Span gap | Right document, only part of a multi-span answer found |
| ICR | Incorrect region | Right document, wrong section |
| OVR | Over-retrieval | Right region, chunk much coarser than the evidence |
| OK | Correct | Retrieved span covers the ground-truth evidence |

Classification is pure arithmetic on character indices — no embeddings, no model calls, no judgment. Scoring is per-span (not merged-character-set) to correctly handle multi-span evidence (43% of LegalBench-RAG queries).

Retrieval metrics (P@1, R@8) are character-overlap ratios computed from these spans. They are deterministic and reproducible.

**Layer 2 — LLM-judged answer quality (separate, clearly labeled).** Two metrics, both judged by a pinned model (DeepSeek-v4-flash, temperature 0, thinking disabled) held constant across all comparisons:

- **Correctness:** Does the answer convey the same information as the ground-truth evidence? Span-informed: the judge sees both the system's answer and the golden evidence text.
- **Faithfulness:** Is each answer claim entailed by the retrieved context? Holistic groundedness (RAGAS definition): each claim judged against the full retrieved context.

### The benchmark regime

All headline numbers are measured on the **combined-index regime**: all 4 LegalBench-RAG corpora (ContractNLI, CUAD, MAUD, PrivacyQA — 72 mini-split documents, 11,524 SAC chunks) pooled into one index. Every query competes against cross-corpus distractors. Both dense (sqlite-vec, voyage-4) and sparse (BM25) channels search the same combined pool — channel-matched, verified.

The **two-arm controlled comparison** isolates the config-stack contribution:
- **Arm 0 (foundation):** SAC + RRF fusion, no routing, no selector, no reranker. Same index, same embedder, same judge.
- **Arm 1 (full config):** SAC + CC fusion (per-corpus alpha) + always-on routing (top-3) + unconditional selector (wider-pool top-30, re-synth on promotion) + no reranker + single-shot.

The delta between arms is the controlled, method-level claim — everything else cancels.

### Ruler calibration (Finding 44)

Before any external comparison, the measurement layer was empirically calibrated against the published LegalBench-RAG baseline (arXiv 2408.10343, Table 5). The paper's exact stack was replicated (RCTS 500-char, text-embedding-3-large, dense-only cosine, sqlite-vec, combined index) and run through our measurement layer.

Result: 3 of 4 corpora (MAUD, CUAD, PrivacyQA) reproduce within a ~2-3pp embedding-drift floor. ContractNLI diverges due to benchmark-file provenance (our benchmark file was not generated by the paper's pipeline). The ruler computes correctly — divergences are input-data differences, not measurement bugs.

### Verify-before-trust discipline

Four silent measurement bugs were caught during the headline session before they could ship wrong numbers. Each was caught by verification checks, not by the numbers looking wrong:

1. **Pro model-ID alias** (Finding 34): `PRO_MODEL="deepseek-chat"` routed to flash, not Pro. Every prior "Pro" test was actually flash. Caught via billing + API docs. Fixed with served-model logging.
2. **BM25 channel mismatch**: Combined-index dense searched mini-doc chunks; BM25 searched full parquets (96K vs 4,496 for CUAD). Fixed by filtering BM25 to the same mini-doc set.
3. **Span-offset bug**: Qdrant payloads don't store character spans (spans live in parquets). Combined-index builder defaulted to (0,0). All P@k/R@8 computed as ~0. Fixed by parquet span lookup; spot-checked correct.
4. **Chunk-size inconsistency** (Finding 46): MAUD uses 2048-char chunks; the other three use 512-char. Previously undocumented — confounds MAUD's external P@k comparison.

This is the project's thesis in practice: measurement rigor requires systematic verification at every step, because silent failures look identical to correct results in the output.

### External comparison (system-vs-system)

Retrieval metrics on the 3 un-confounded corpora (512-char SAC, comparable to the paper's 500-char RCTS). Published baselines from arXiv 2408.10343, Table 5: RCTS chunking, text-embedding-3-large, dense-only, no reranker.

| Corpus | Meridian P@1 | RCTS P@1 | Meridian R@8 | RCTS R@8 |
|--------|-------------|----------|-------------|----------|
| ContractNLI | 0.422 | 0.066 | 0.810 | 0.250 |
| CUAD | 0.394 | 0.020 | 0.814 | 0.317 |
| PrivacyQA | 0.297 | 0.144 | 0.579 | 0.424 |

**Framing:** This is a whole-stack comparison — Meridian (SAC + CC + hybrid dense/sparse + routing + selector, voyage-4) vs a bare baseline (RCTS, dense-only, text-embedding-3-large). The advantage bundles embedder quality + hybrid retrieval + fusion + routing. It is system-level evidence, not a single-component ablation.

MAUD is excluded from this table — its 2048-char chunks create a chunk-granularity confound with the paper's 500-char RCTS that mechanically deflates character-overlap precision (Finding 46). ContractNLI is caveated: benchmark-file provenance differs from the paper's (Finding 44).

### NFCorpus transfer (retrieval stack only)

First non-legal test. NFCorpus (BEIR medical IR, 3,633 docs, 323 queries, nDCG@10):

| System | nDCG@10 |
|--------|---------|
| Meridian (CC alpha=0.1, routing OFF) | 0.399 |
| BM25 + cross-encoder reranker | 0.350 |
| BM25 | 0.325 |
| contriever | 0.328 |
| TAS-B | 0.319 |
| DPR | 0.189 |

Above the classic BEIR baselines (2021 paper). These are dated single-method baselines — modern dense retrievers are comparable. Frame as "above classic baselines," not SOTA.

**What transferred:** the retrieval stack (hybrid + CC fusion, +5.6pp over RRF).

**What did NOT transfer / was not tested:** the span-forensic measurement framework. BEIR provides document-level relevance, not character spans — Layer 1's taxonomy could not run. Routing was correctly self-disabled (hurts on dispersed-relevance medical text). This is a retrieval-transfer result, not a measurement-framework-transfer result.

**The genuine finding:** routing is a concentrated-relevance technique, not universal. It monotonically hurts on NFCorpus (OFF > k=10 > k=5 > k=3). The sweep auto-detected this — consistent with the legal finding that routing benefit tracks document-discrimination difficulty.

## Limitations

- **Routing degrades on topically-homogeneous cross-corpus retrieval.** ContractNLI routing drops to 76% in the combined regime (NDA/commercial-contract confusion). 47/194 queries get zero correct-document chunks.
- **Routing hurts on dispersed-relevance corpora.** Confirmed on NFCorpus. Routing is a concentrated-relevance technique, not universal.
- **Span-forensic framework requires character-span ground truth.** Layer 1's taxonomy does not apply to document-level relevance benchmarks (most of BEIR, MS MARCO). This is a scope boundary.
- **MAUD external comparison confounded** by 2048-char vs 500-char chunk granularity.
- **ContractNLI external baseline caveated** — benchmark-file provenance differs from the paper's generation pipeline.
- **Affirmative-only evaluation.** All four LegalBench-RAG corpora contain only affirmative-answer queries. Correctness measures recall, not false-positive rate.
- **Synthesis variance band is ±2-4pp** (Finding 40). Quality deltas below this are indistinguishable from run-to-run nondeterminism.
